# 研究引き継ぎマニュアル: 12誘導心電図再構成手法

## 1. ハードウェアと計測の引き継ぎ

### 1.1. 機器の保管場所と運用上の注意点

*   **16chシートセンサ**および**無線計測モジュール（Evobrain）**の保管場所や詳細な運用上の注意点（断線しやすい箇所、接続の順番、バッテリー管理など）については、直接口頭で引き継ぐのが最も確実です。

### 1.2. 計測プロトコル

*   **センサの貼り付け位置**:
    *   修士論文で用いたデータ計測においては、**標準12誘導心電図の電極と重ならないよう、大まかな位置にシートセンサを貼り付けた**。特に厳密な位置規定は設けていない。
    *   拡張型データ計測を行う際は、**脇の位置をシートセンサの上部として、そこから体の正中線に沿ってシートセンサが配置されるように貼り付け位置を調整している**。

## 2. データセットと前処理の引き継ぎ

### 2.1. 生データの取得と保存

生の心電図データは、16chシートセンサと標準12誘導心電図で取得方法と保存場所が異なります。

*   **16chシートセンサデータ**:
    1.  `sheet_sensor/new_16ch.bat` を実行して計測します。
    2.  計測されたデータは、`ecg_project/data/raw/sheet_sensor_csvdatas/` ディレクトリに自動的に保存されます。

*   **標準12誘導心電図データ**:
    1.  別途計測したデータ（`.mwf`形式など）を、まず手動で `ecg_project/data/raw/` 以下の個人用ディレクトリ（例: `takahashi_test/`）に保存します。
    2.  その後、`dataset_creation/mfer_to_12ch.py` を実行します。
    3.  これにより、`.mwf` ファイルがCSV形式に変換され、同じディレクトリ内に保存されます。

### 2.2. 前処理パイプライン

*   **メインスクリプト**: `dataset_creation/Make_dataset_0120_16ch_synchro_per_heart.py`
*   **役割**: このスクリプトが、本研究における前処理のほぼ全て（フィルタリング、リサンプリング、同期処理、心拍ごとの切り出し等）を担っています。
*   **注意点**: データセットを作成する際は、このスクリプトの内部処理（特にファイルパスやパラメータ）をよく理解した上で実行する必要があります。

#### 2.2.1. PQRST波形ポジションの検出方法 (`manual_setting`)

`Make_dataset_0120_16ch_synchro_per_heart.py` や `synchro_pseudo.py` など、データセット作成の主要スクリプトでは、心拍の各成分（P波、QRS波など）の位置を特定する方法を `manual_setting` パラメータで選択できます。

*   **`manual_setting = 1` (手動設定)**
    *   実行するとグラフが表示され、ユーザーが `p_onset`, `p_peak`, `p_offset`, `q_peak`, `s_peak`, `t_onset`, `t_peak`, `t_offset` の各点を順番にクリックすることで、波形ポジションを直接指定できます。
    *   Y軸（振幅）の位置は関係なく、クリックした時点のX軸（時間）の位置がポイントとして保存されます。

*   **`manual_setting = 2` (ファイルから読込)**
    *   過去にモード `1` または `3` で実行して保存されたポジションデータ（`ponset_toffset_*.csv`）が存在する場合、それを再利用します。

*   **`manual_setting = 3` (自動検出)**
    *   `neurokit2` ライブラリを用いて、各心拍の波形ポジションを自動で検出します。

*   **使い分けのヒント**:
    *   健常者から取得した綺麗なデータに対しては、まず `3` (自動検出) を試すのが効率的です。
    *   `neurokit2` がうまくピークを検出できないデータ（ノイズが多い、P波が不明瞭など）に対しては、`1` (手動設定) を用いて正確なアノテーションを行う必要があります。

#### 2.2.2. `Make_dataset_0120_16ch_synchro_per_heart.py` の主要パラメータ

このスクリプトは過去のコードも含まれており行数・パラメータが多いですが、後輩がデータセット作成時に特に注意すべき重要な設定は以下の通りです。

*   **`args.reverse`**: `on` または `off` で指定します。
    *   既存のNeuroKit2ライブラリを用いたR波ピーク検出は、R波ピークが正の値（上向き）でないと適切に機能しないことが多いです。
    *   実行後に生成されるR波検出結果のグラフを確認し、波形が反転している場合は `on` を選択して信号の正負を反転させてください。
*   **`args.raw_datas_dir`**: 生波形が保存されているディレクトリのパスを指定します。
*   **`args.dataset_output_path`**: 前処理後のデータセットの保存先ディレクトリのパスを指定します。
*   **`args.TARGET_CHANNEL_12CH`**: R波ピーク検出による時刻同期の基準となる標準12誘導心電図の誘導（例: `"A2"`）を指定します。
*   **`args.name`, `args.date`**: これらのパラメータは、`select_name_and_date()` 関数が自動で取得します。そのため、事前に `config/name_dic.py` ファイルを編集し、対象の被験者の名前と計測日を設定しておく必要があります。

#### 2.2.3. 拡張型データ計測手法（`synchro_pseudo.py`）

*   **目的**: シートセンサの貼り付け位置をずらした場合のデータセット（拡張データ）を生成するために使用します。
*   **スクリプト**: `dataset_creation/synchro_pseudo.py`
*   **実行手順**:
    1.  スクリプト内の `raw_datas_dir` に、対象となる生データが格納されているパスを指定します。
    2.  `args.pos` パラメータの値を `center_1`, `center_2`, `center_3`, `center_4`... と順番に変更しながら、繰り返しスクリプトを実行します。
    3.  実行ごとに、指定された位置に対応するデータセットが生成されます。
*   **データの特徴**: この手法で作成されるデータは、同期処理が行われていない非同期データです。R波ピークを基準として、心拍ごとのデータに分割されています。

##### 主要パラメータ

*   **`rate`**: 16chセンサデータのリサンプリングレート。`122.06Hz` に固定されています。
    *   この手法では、単一計測のようにRRI（R-R間隔）を基に最適なサンプリングレートを求めることができないため、この値に固定されています。
*   **`average_beats_num`**: 16chセンサデータに対して、何心拍分のデータをアンサンブル平均するかを指定します。
    *   この平均処理を見越して、16chセンサのデータは通常約40秒間取得されています。
*   **`enable_averaging`**: 16chセンサデータに対して、アンサンブル平均処理をそもそも実行するかどうかを選択するフラグです。

### 2.3. データ拡張 (Data Augmentation)

*   **関連ディレクトリ**: `machine_learning/`
*   **概要**: STやPQ部分の時間伸長といったデータ拡張に関する実装は、主に `machine_learning` ディレクトリ内のコードで行われています。

## 3. AIモデル (U-Net) と学習環境の引き継ぎ

### 3.1. コードの場所と実行方法

*   **U-Netの学習・推論コード**: `machine_learning/train_unet.py` などのファイルに実装されています。
*   **実行スクリプト**: 学習や評価を実行するためのシェルスクリプトは `run_unet.sh` または `grid_search_and_best_param_train.py` などが利用できます。

#### 3.1.1. `grid_search_and_best_param_train.py` の主要パラメータ

このスクリプトは、様々な機械学習モデルのハイパーパラメータを効率的に探索するためのグリッドサーチを行います。

*   **パラメータ定義**: スクリプトの31行目以降で、グリッドサーチの対象となるエポック数、データセット名、および各機械学習モデル（`cnn_lstm`, `cnn`, `lstm`, `unet`）ごとに探索するハイパーパラメータの配列が定義されています。これらの配列を調整することで、探索範囲を変更できます。
*   **チャンネル数の指定**: 289行目の `cli_args.num_channels` で、使用するデータセットのチャンネル数（15または16）を指定します。


### 3.2. 実行環境

*   実行環境に関する具体的な推奨情報（Pythonバージョン、ライブラリ、GPU要件など）は、このドキュメントでは省略します。後輩は、既存のセットアップやプロジェクトの依存関係から環境を構築する必要があります。

### 3.3. 学習時のハイパーパラメータ

*   学習時の重要なハイパーパラメータに関する具体的な推奨値や調整ポイントは、このドキュメントでは省略します。後輩は、`arguments.py` や関連スクリプトの内容を調査し、自身で適切なハイパーパラメータを見つける必要があります。

### 3.4. 精度向上のコツと失敗談

*   **データ量とモデルの安定性**:
    *   データ数が少ない場合、U-Netモデルよりも、`CNN` や `VAE` といったシンプルなモデルの方が学習が安定し、良い結果が得られる場合があります。
    *   データ数を十分に増やすことができれば、修士論文で用いた `U-Net` モデルがより高い精度を発揮する可能性が高いと推測されます。

## 4. 技術的な課題と今後の展望（後輩への期待）

### 4.1. データ収集とデータ拡張

*   **課題**: 現在の研究はまだデータ数が十分とは言えません。モデルの汎化性能や頑健性を高めるためには、より多くの心電図データを収集することが必須です。
*   **展望・提案**: データ収集と並行して、先行研究にあるような **COMSOLシミュレーション** を活用したデータ拡張手法を導入することを推奨します。これにより、限られた実データからでも多様な学習データを生成し、モデルの性能向上に繋がる可能性があります。

### 4.2. モデル性能評価の高度化

*   **課題**: 現在のモデル性能評価はRMSEやPCCといった一般的な波形評価指標に依存しています。心電図の診断的意義をより正確に反映するためには、より専門的な評価指標の導入が望まれます。
*   **展望・提案**: **Weighted Diagnostic Distortion (WDD)** の評価指標を実装し、モデル評価に活用することを強く推奨します。これは心電図特有のP波、QRS波、T波といった各成分の歪みを重み付けして評価するものです。
    *   （私が）試験的に実装を試みているため、**`machine_learning/calculate_wdd_from_csv.py`** を参考にしてください。
    *   **注意点**: WDDの実装はNeuroKit2のようなピーク検出ライブラリに大きく依存しており、安定した結果を得るためには信号品質やライブラリの挙動を深く理解する必要があります。すぐに導入するのが難しい場合もあるため、焦らず段階的に取り組んでください。
